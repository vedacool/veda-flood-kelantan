| 1 | **`run_sql` "read-only" check is a prefix regex — writes pass** | `app/adapters/zetaris.py:33` `READ_ONLY`; verified `WITH x AS (SELECT 1) INSERT INTO t SELECT * FROM x` and `SELECT reflect('java.lang.Runtime','getRuntime')` are accepted. | 2 | **A `--` comment silently swallows the rest of the query** | `zetaris.py:73` joins lines: `SELECT … -- latest only\nWHERE station_key='X'` → `… -- latest only WHERE …` → WHERE ignored, every station returned. | 3 | **A re-scrape can wipe good flood thresholds** | `app/ingest/jps.py:155-158` upsert sets `normal/alert/warning/danger_m = EXCLUDED.*`; `to_number('-')` → None, so one bad JPS render erases stored alert/danger levels | `COALESCE(EXCLUDED.x, stations.x)` for thresholds, jps_id, river, district; trace a warning when an incoming threshold is NULL |
| 4 | **15-min collector dies on database errors** (running now via VEDA Start) | `jps.py:209` catches only `JpsParseError, PgError, RequestException`; a `psycopg` error after connecting (e.g. Postgres restart, missing table) escapes and ends `--loop`. JPS shows only the latest reading → missed history is lost. Contradicts how-it-works ("keeps going after a failed cycle") | Wrap `psycopg.Error` as `PgError` in `store()`, catch `OSError`; in `--loop` catch any `Exception` (not KeyboardInterrupt), trace `failed`, continue |

## P2 — schedule
- **Number parsing accepts impossible values** — `jps.to_number`: `'7,47'`→747.0 (decimal comma read as thousands), `'nan'`, `'inf'`, `'9999'` kept; `zetaris.coerce('1e400')`→inf (all verified). Fix: reject non-finite, treat `abs(v) ≥ 9999` as missing, strip commas only in `\d{1,3}(,\d{3})+`; plausibility CHECK on `level_m`.
- **Postgres superuser reachable from the network** — `docker port veda-pg` → `0.0.0.0:5433` and `[::]:5433` (verified). On hackathon Wi-Fi this is exposed (strong password, but still). Fix: `-p 127.0.0.1:5433:5432` in `scripts/setup_pg.py` (container re-create needed).
- **Non-object JSON crashes adapters without a trace line** — `nightshift.py` / `zetaris.py` call `.get` on a list/str body (e.g. 429 with `{"error":"rate limited"}`) → `AttributeError`, not the module's error type, so callers' fallbacks miss it. Fix: `isinstance(payload, dict)` guard → existing classify/retry path.
- **`run_ddl` allow-list allows SSRF / view replacement / drops** — `CREATE LIGHTNING REST TABLE … REQUEST(url "http://169.254.169.254/…")`, `CREATE OR REPLACE SCHEMASTORE VIEW` over a trusted view. Fix: agents get named DDL templates with host allow-list (`api.data.gov.my`, `api.open-meteo.com`) and `veda_*` names; raw `run_ddl` only from `scripts/` (guard test). Before the self-healing work.
- **Secret-scan guard misses common shapes** — `tests/test_architecture.py`: `password "…"` (our own DDL style), `postgresql://u:pw@host`, `{"api_key": "…"}`, unquoted `KEY=…` not detected; scans working tree not staged blobs. Fix: add patterns; read staged content (`git show :path`); run gitleaks on history before going public.
- **Agent guard checks top-level module names only** — `from app.adapters import pg` (superuser) / `app.ingest` / `importlib` pass; `setup=1` passes. Fix: block those in `app/agents/`.
- **Per-call worst case > 10-minute run deadline** — Nightshift 180 s × 4 attempts (+ repair) ≈ 12–24 min; Fix: an overall deadline argument or lower timeouts.
- **Docker calls in `setup_pg.py` have no timeout** (can hang forever); `docker start` return code ignored.
- **JPS collector ignores SAMPLE_MODE** and fetches live before checking Postgres config. Fix: refuse live fetch in SAMPLE_MODE; check config first.
- **A reading with no level blocks the real value for the same time** — `ON CONFLICT DO NOTHING` keeps a NULL. Fix: skip NULL levels or `DO UPDATE … COALESCE`.
- **No SAMPLE_MODE fixtures committed yet** (`data/fixtures/` empty) — tracked by B-18; record once agent SQL is stable.
- **Trace context not carried into plain worker threads** (`ThreadPoolExecutor` → "before start_run"); FastAPI's threadpool is fine. Document or use `copy_context()`.

## P3 — polish
- Trace redaction gaps (a quoted password containing spaces, URL credentials, `X-Api-Key`, Basic auth) and over-redaction (`"secret: none"` → `"secret: *** of this"`; any env var named *KEY*/*TOKEN* masks its value everywhere). Raw exception text printed unredacted in `setup_pg.py` / `zetaris.main`.
- `normalize_sql` collapses whitespace inside string literals (`'Kg  Baru'` → `'Kg Baru'`); `dict(zip(columns,row))` silently drops on length mismatch.
- 15-min rule uses file mtime (future mtime → negative age). No rotation of `logs/` traces (~96 files/day) or `data/cache/jps` (~2.7 MB/day).
- Schema: no FKs (`river_levels`, `places.nearest_station_key`), no threshold-order or future-time CHECKs; `IF NOT EXISTS` never adds new columns. `schema_statements()` splits on `;` / `--` even inside literals (latent).
- Ingest connects as Postgres superuser (use a writer role). `station_key` from href not validated (`^[A-Za-z0-9_]{1,32}$`); no response size cap.
- Supply chain: 13 transitive deps unpinned, no hashes, no CVE scan run (no pip-audit available). Licences OK (psycopg LGPL-3.0 used as a library; certifi MPL-2.0; rest MIT/BSD/Apache/PSF).
- Duplication: secret patterns (trace.py vs test_architecture.py, different thresholds), `imports_of` (codemap vs tests; codemap mis-resolves `from . import x` in `__init__`, latent), SAMPLE_MODE parsing ×4, PG host/port ×2 → an `app/config.py`.
- Docs drift: how-it-works omits `run_ddl(setup=)`, `chat(temperature, target_agent)`, says "6 guard rules" (7); BUILD_BRIEF table list lacks `stations`, says "3 retries" (Zetaris does 2 by decision); README lacks venv/pip/.env setup and collector usage.
- Mixed time zones: run ids / snapshot names in local time, sentences in machine zone (wrong on a judge's laptop abroad) → use MYT explicitly.
- `spikes/` (tracked, direct HTTP, own `run_sql`) could be mistaken for VEDA code → README note or remove before public. Spike 3 set the superuser password on `veda_zetaris` earlier (since replaced by `VEDA_PG_RO_PASSWORD` in B-05; spike datasources were dropped).
- Hooks: fail closed, but `--no-verify` skips them and a fresh clone must set `core.hooksPath` → run the same checks in CI.
- Ctrl+C mid-cycle leaves no `run_end` trace line (DB rolls back cleanly).
